本仓库未引入任何第三方日志框架或统一的日志模块，整体采用浏览器原生 `console` API 进行调试与错误输出，属于最基础的日志方式。

1. 使用的系统与工具
- 仅使用浏览器/Node 内置的 `console.error` 进行错误记录，未发现 `console.log`、`console.warn`、`console.debug` 等结构化日志调用。
- 没有独立的 logger 初始化文件、日志级别配置、日志路由或 sink 机制。

2. 关键位置
- `src/components/CommitGraph.tsx`：在 Canvas 渲染器初始化失败时通过 `console.error("Failed to initialize graph renderer:", e)` 输出错误堆栈信息，是仓库中唯一可见的日志输出点。
- `electron/main.ts`：主进程通过 `safeHandler` 将异常统一包装为 `{ success: false, error: err.message || String(err) }` 返回给渲染进程，由前端组件自行处理错误提示，而非写入日志文件。

3. 架构与约定
- 无集中式日志模块，各组件按需直接调用 `console.error`。
- 错误传播走 IPC + Promise 返回值（`success/error` 字段），不依赖日志文件定位问题。
- 开发模式下 Electron 会打开 DevTools（`mainWindow.webContents.openDevTools()`），便于在控制台查看 `console.error` 输出。

4. 约定与约束
- 当前代码库未定义统一的日志级别策略、结构化字段规范或日志输出目标（文件/远程收集器等）。
- 所有可观测性主要依赖浏览器控制台与 Git 操作返回的错误对象，未实现持久化日志。
